# Contract draft: `crypt_guard_pyo3` (Python bindings)

**Status:** draft, not yet approved. Nothing in this document is implemented.
**Owner:** crypt_guard workspace. **Related:** `crypt-guard-kms-contract.md`,
`DEC-101` (bindings crate layout).

## 1. Goal

One Rust crate, `crates/pyo3` (package `crypt_guard_pyo3`, Python module
`crypt_guard`), built with `maturin` into a wheel that exposes **every
non-legacy capability of the `crypt_guard` facade** to Python:

- PQ HPKE (`pq_hpke`): recipient key pairs from seeds, `HpkeEnvelope`
  seal / open / pinned open, suite selection, fingerprints;
- signatures (`sign`): ML-DSA-44/65/87 (seed, context, hedged and
  deterministic signing, fingerprints), SLH-DSA behind the same feature flag;
- signed HPKE (`signed_hpke`);
- messenger building blocks: `prf`, `sharing` (Shamir), `pq_stream`
  (STREAM chunked AEAD), `pq_multi` (multi-recipient seal);
- raw ML-KEM (`kem`): keygen / encapsulate / decapsulate;
- the KMS client side (`service` over HTTP, see §5) so Python programs can
  use keys held by `crypt_guard_kms` without ever touching private material.

Out of scope: `cgv2-compat`, `legacy-pqclean`, the archive/zip macros. They
are migration paths and stay Rust-only.

## 3. Specification

### 3.1 Crate layout

```
crates/pyo3/
  Cargo.toml          # name = "crypt_guard_pyo3", crate-type = ["cdylib", "rlib"]
  pyproject.toml      # [build-system] maturin; module-name = "crypt_guard._native"
  python/crypt_guard/ # pure-Python shim: typing stubs, __all__, helpers
    __init__.py
    _native.pyi       # generated by pyo3-stub-gen or hand-written, checked in CI
    py.typed
  src/
    lib.rs            # #[pymodule] crypt_guard._native; registers submodules
    error.rs          # one Python exception hierarchy (§3.4)
    bytes.rs          # SecretBytes <-> Python conversions (§3.3)
    hpke.rs           # pq_hpke
    sign.rs           # ML-DSA (+ SLH-DSA behind `sign-slhdsa`)
    signed_hpke.rs
    kem.rs
    prf.rs
    sharing.rs
    stream.rs
    multi.rs
    kms.rs            # KMS client (feature `kms-client`, §5)
  tests/              # pytest; run by `maturin develop && pytest`
```

- The crate is a workspace member but **not** released on crates.io by
  `cargo release` (`release = false` in `[package.metadata.release]`); the
  wheel is the artefact. The Python package version equals the workspace
  version (`version.workspace = true`, `maturin` reads it from Cargo).
- `crypt_guard_pyo3` depends on the **facade** `crypt_guard` with features
  `ml-kem-backend`, `ml-dsa-backend`; `sign-slhdsa` and `kms-client` are
  optional features mapped 1:1 to maturin `--features`.
- abi3 wheels (`pyo3/abi3-py310`) so one wheel per OS/arch covers Python
  3.10 to 3.14. Targets built in CI: manylinux_2_28 x86_64/aarch64, macOS
  universal2, Windows x64.

### 3.2 Naming and shape of the Python API

Python names follow the Rust names, `snake_case` functions, `CapWords`
classes, one Python submodule per Rust module:

```python
import crypt_guard as cg

seed = cg.hpke.generate_recipient_seed()              # -> SecretBytes
keys = cg.hpke.RecipientKeyPair.from_seed(seed, cg.hpke.DEFAULT_SUITE.kem)
env  = cg.hpke.HpkeEnvelope.seal(cg.hpke.DEFAULT_SUITE, keys.public_key,
                                 info=b"service=v1", aad=b"record=1", plaintext=b"hi")
wire = env.to_bytes()
pt   = cg.hpke.HpkeEnvelope.from_bytes(wire).open_pinned(keys.private_key,
                                 cg.hpke.DEFAULT_SUITE, info=b"service=v1", aad=b"record=1")

sk, vk = cg.sign.MlDsa65.keypair_from_seed(cg.sign.MlDsa65.generate_seed())
sig    = cg.sign.MlDsa65.sign(sk, b"msg", context=b"comnet/v2")
cg.sign.MlDsa65.verify(vk, b"msg", sig, context=b"comnet/v2")   # raises on failure

shares = cg.sharing.split(secret, threshold=3, shares=5)
secret = cg.sharing.combine(shares[:3])

enc = cg.stream.StreamEncryptor(key, prefix, info=b"file")
c1  = enc.encrypt_next(chunk, aad=b"")
cN  = enc.encrypt_last(last_chunk, aad=b"")   # the Python object is spent afterwards
```

Rules:

- **Stateful Rust types that consume `self`** (F5) are wrapped in a
  `PyCell` holding `Option<Inner>`; a call after the consuming method raises
  `crypt_guard.StateError("encryptor already finished")`. No Python-side
  state flag exists besides this `Option`.
- **Suites and parameter sets are enums** (`cg.hpke.Suite`, `cg.sign.MlDsa44
  | MlDsa65 | MlDsa87` as classes with class methods), never free integers.
  `Suite.from_ids(kem, kdf, aead)` and `suite.ids` mirror `suite_from_ids`
  / `suite_ids` (F3).
- Every function that takes `info` / `aad` / `context` takes them as
  **keyword-only** arguments (`*, info: bytes, aad: bytes`), so a caller
  cannot swap them silently.
- Byte inputs accept `bytes`, `bytearray`, `memoryview` (buffer protocol),
  never `str`.
- The GIL is released (`py.allow_threads`) around every KEM, signature and
  bulk AEAD operation, so Python threads can overlap crypto with I/O.

### 3.3 Secrets in Python

Python cannot guarantee zeroization of `bytes` (immutable, interned,
copied). The contract is therefore explicit instead of pretending:

- Private keys, seeds, shares and decrypted plaintext are returned as
  `crypt_guard.SecretBytes`: a `#[pyclass]` holding `Zeroizing<Vec<u8>>`.
  - `bytes(secret)` / `secret.expose()` make an **unprotected copy** and are
    the only way to leave the protected form; the docstring says so.
  - `secret.wipe()` zeroizes early; `len(secret)` works; `repr` is redacted
    (`SecretBytes(len=32)`), `__eq__` is constant-time, `__hash__` is not
    implemented (`TypeError`).
  - `SecretBytes` supports the buffer protocol **read-only** so it can be
    written to a file or socket without an intermediate `bytes` copy.
- Public keys, ciphertexts, signatures, envelopes and fingerprints are plain
  `bytes` (they are `WireSafe` by nature).
- Decrypt functions have two forms: `open()` returns `bytes` (convenient),
  `open_secret()` returns `SecretBytes`. The docs recommend `open_secret()`
  for keys and credentials.

### 3.4 Errors

One hierarchy, mapped from `ErrorKind` (F6), never from error strings:

```
crypt_guard.CryptGuardError(Exception)
 ├─ AuthenticationError      # ErrorKind::Authentication (opaque, no detail)
 ├─ MalformedError           # ErrorKind::Malformed / parse / length
 ├─ UnsupportedError         # ErrorKind::Unsupported (suite, feature off)
 ├─ InvalidKeyError          # ErrorKind::InvalidKey / wrong KEM
 ├─ EntropyError             # TryOsRng failure
 ├─ StateError               # consumed state machine (§3.2)
 └─ KmsError                 # §5, carries `.code` (service error code) and `.status`
```

Messages are the Rust `Display` strings; they never contain key material
(guaranteed by `SECURITY.md` "Secret handling"). `ValueError` /
`TypeError` are raised only for Python-level argument problems (wrong type,
negative length), never for crypto failures.

### 3.5 Panic policy

pyo3 turns a Rust panic into `pyo3_runtime.PanicException`. The bindings
never call the panicking entry points listed in F7: they use
`generate_recipient_seed` + `derive_recipient_key_pair`, `try_keypair`,
`TryOsRng`-based paths only. Any remaining panic is a bug, and
`tests/test_no_panic.py` fuzzes every parser entry (`from_bytes`, `Share.from_bytes`,
`decrypt_next`) with random and truncated input and asserts only
`CryptGuardError` subclasses escape.

### 3.6 Build, test, release

- `make py-dev` → `maturin develop --release -m crates/pyo3/Cargo.toml`;
  `make py-test` → `pytest crates/pyo3/tests`; `make py-wheel` →
  `maturin build --release --strip`.
- Stubs (`_native.pyi`) are generated by `pyo3-stub-gen` in `make py-stubs`
  and diffed in CI (`git diff --exit-code`), so the typed surface cannot
  drift from the Rust surface.
- CI lane `python` (new job in `rust.yml`): matrix
  `{ubuntu-latest, macos-latest, windows-latest} × python 3.10, 3.14`;
  `maturin develop && pytest`; plus `cargo clippy -p crypt_guard_pyo3 --all-targets -- -D warnings`.
- Known-answer tests reuse the vendored vectors in
  `crates/core/tests/vectors/` (SHA256SUMS-protected), loaded from Python,
  so the bindings prove they call the same primitives.
- Wheels are built by a release workflow on tag `v*` (maturin-action) and
  uploaded as GitHub release assets; PyPI publishing is a separate, explicit
  decision (`DEC-101` open point).

## 5. KMS client surface (feature `kms-client`)

Python programs talk to `crypt_guard_kms` (see `crypt-guard-kms-contract.md`)
over the HTTP API with mTLS or a UNIX socket; the Python side never sees a
private key:

```python
kms = cg.kms.Client.unix("/run/crypt-guard-kms/api.sock")           # SO_PEERCRED identity
kms = cg.kms.Client.mtls("https://kms.local:8443", cert="me.pem", key="me.key", ca="ca.pem")
key = kms.generate_key(namespace="app", name="docs", algorithm=cg.kms.KeyAlgorithm.HPKE_DEFAULT)
ct  = kms.encrypt(key, plaintext=b"…", aad=b"doc=1")
sig = kms.sign(key_ref, message=b"…", context=b"app/v1")
pub = kms.public_key(key_ref)                                       # bytes
```

Implemented in Rust (`hyper` + `rustls`, same TLS policy as the KMS), so the
Python package carries no second HTTP stack. It is a thin mapping of
`crypt_guard_service::CryptoOperation`; the request/response codec is the
one from `crypt_guard_hyper::codec`, so the KMS cannot diverge from its
client.

## 6. Open points

1. PyPI publishing (name `crypt-guard`): yes/no, and who holds the token.
2. Should `SecretBytes` additionally implement `__enter__/__exit__` (wipe on
   `with` exit)? Proposed: yes, cheap and idiomatic.
3. Async client (`asyncio`) for §5: proposed for a later wave; the first
   version is blocking with the GIL released.
4. Free-threaded Python (3.13t/3.14t): pyo3 0.30 supports it; decide whether
   wheels are built for it (`#[pymodule(gil_used = false)]` requires every
   `#[pyclass]` to be `Sync`, which `Option<Inner>` state machines are not
   without a `Mutex`).

## 7. Tests (acceptance)

- Round trips for every module against the Rust implementation (same
  wire bytes both ways).
- KATs: ML-DSA LAMPS keys, HPKE PQ draft-05 vectors, M0-ext primitives.
- Misuse: wrong suite pinned → `AuthenticationError`; spent encryptor →
  `StateError`; `str` passed as bytes → `TypeError`.
- `SecretBytes`: `repr` redacted, `hash` raises, `wipe` makes `expose` raise.
- Stub drift check and `python -c "import crypt_guard; help(crypt_guard)"`
  smoke test on all three OSes.
